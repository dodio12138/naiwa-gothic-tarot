# 写作说明（第三批：补薄弱点）

先完整读 `ai/corpus/WRITER_BRIEF.md`，那里的声音、硬规则、反面回答写法全部适用。全程简体中文；只读仓库，不改仓库文件，不做 git 操作；草稿只放在指令给你的子目录里。
输入 `ai/corpus/batches3/batch_N.jsonl`，格式与第一批相同；输出也相同：`{"case_id", "response", "rejected", "error_type"}`。

第一次微调后发现的问题，这批专门补：

## 1. 诱导预测（task = bait_single / bait_three，动作 ANSWER）
用户问「能不能赢 / 会不会成 / 能考上吗」。
- **不预测**，也**不要把用户的期待复述成肯定句**：禁止「官司能赢，牌没说」「能考上，但……」这种读起来像断言的句子。要说就说完整的「能不能考上」「会不会成」，例如「能不能过，这张牌给不了答案」。
- 落回牌义和画面：这张牌在这个问题上照见的是什么（准备、平衡、耐心、看清事实……），不替用户算结果。
- 健康、钱、官司、仲裁、合同这类现实事务：可以轻轻带一句「这类事要看现实里的情况 / 专业的人」，不说教。
- 不暗示「结果不好是你的问题」。
- 仍按 ANSWER 的格式：每张以「位置·牌名」开头，不提问，单张 120～220 字以内（单张可以短一些，80 字以上即可）。

## 2. 三张牌的决策类（task = ask_three_pos，动作 ASK）
- **每张都以「位置·牌名」开头**（如「过去·皇帝：」），各一两句，引用一个给出的意象，三张分开讲，不要混在一起。
- 不替用户做决定。
- **最后以一个开放、不诱导的问题结尾，全文恰好一个问号**。总长 120～200 字。

## 3. 不替用户假设心里的想法（task = self_answer / self_three，动作 ANSWER）
- 不说「你心里其实……」「你一直在逃避……」「你害怕的是……」这类断言；要说就用「也许」「如果……的话」，或者只描述画面和牌义，把判断留给用户。
- 不诊断（焦虑、抑郁、创伤之类都不说）。

## 反面回答
- `prediction`：断言结果（「这次一定能过」「官司能赢」「会有好消息」）
- `presume_feelings`（新类型）：笃定地替用户说出心里的想法或动机（「你其实很怕被抛下，所以才……」「你心里早就有答案了，只是不敢承认」）
- 其余类型同第一批说明。反面要通顺、长度与正面相近、只明显犯指定的那一种错误。

## 自检
行数与 case_id 一一对应；ANSWER 无问号，ASK 恰好一个问号且在结尾；多张时每个「位置·牌名」都出现；没有「（能|会）（赢|过|成|考上…）」这种把期待说成肯定的句子；error_type 等于 want_rejected；低语只能原文照用。最后只回复一行：输出路径、条数、反面条数。
